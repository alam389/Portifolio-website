## Architecture

Personal portfolio (Anthony Lam) on **Next.js 16 App Router + React 19 + TypeScript (strict) + Tailwind CSS v4**. Quiet editorial design: left sidebar rail (bottom bar on mobile), Fraunces display serif for h1/h2 with Geist Sans for prose and Geist Mono for metadata, dark by default with a light toggle. Design intent lives in `.impeccable.md`.

**Routes** (`src/app`): `/` About, `/experience`, `/projects`, `/journey` (three.js particle-terrain globe), `/interests` (+ `/ai`, `/food`, `/active`, `/ai/papers/[id]`), `/resume`, `/pet-lab` (dev only), `not-found.tsx` (the Null Island 404), and `api/resume` (signs a short-lived URL for the private resume PDF in Supabase Storage; needs `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SECRET_KEY`).

**Content layer:** all portfolio content lives in typed modules under `src/data/` (`profile`, `experiences`, `projects`, `journey`, `interests`, `media`, `site`, typed via `types.ts`), consumed via the `@/data` barrel. Never hardcode content in components. To add a field: extend the interface in `types.ts` first, then the data module. Photos and logos come from the public Supabase `media` bucket (URL constant in `src/data/media.ts`, uploaded with `scripts/upload-media.mjs`); the globe data in `public/globe/` is generated by `scripts/generate-globe-data.mjs`.

**Layout** (`src/app/layout.tsx`): theme init script (sets `data-theme` on `<html>` before paint), `SmoothScroll` (Lenis; `scrollToY` is the shared scroll helper), `Sidebar`, `PetMount`, then the page inside `<main>` with a colophon footer.

### Styling conventions

- **Tailwind v4, CSS-first config.** No `tailwind.config.js`. Tokens are CSS variables plus `@theme inline` in `src/app/globals.css` (`bg-background`, `text-foreground`, `bg-surface`). Use `text-foreground/60`-style opacity for secondary text.
- **Theming:** dark default; `[data-theme="light"]` overrides the variables, and the `light:` custom variant styles light-only cases.
- **Grayscale by default.** Any accent is flat and sparing (see `.impeccable.md`). Respect `prefers-reduced-motion`.

### The pixel pet (`src/components/pet/`)

A VS Code Pets–style companion (cat, dog or bunny) that roams the page for every visitor. **Read [`src/components/pet/README.md`](src/components/pet/README.md) before changing it**: it covers the engine/DOM split, the sprite format, personalities and how to test.

Short version:

- `engine.ts` is the pet's brain and physics. **Plain TypeScript, no DOM**, so it can be simulated in Node. `Pet.tsx` is the DOM glue (rAF loop writing `transform`, pointer drag, canvas drawing).
- Sprites are **text grids** (`sprites/cat.ts` etc.), one character per pixel through a palette; the outline is added automatically. Edit art there, then check with `pet-sheet.mjs` or `/pet-lab`.
- The pet is loaded with `next/dynamic` (`ssr: false`) from `PetMount`, and its paw menu (`PawMenu` → `PawPanel`) lives in the sidebar. Settings persist in localStorage (`settings.ts`).
- Page elements become platforms through the selector list in `Pet.tsx`, plus `data-pet-platform` / `data-pet-ignore` attributes. Keep those attributes in mind when adding new layouts.
